This is the shortest path from nothing to a running server. It assumes a C++23
compiler is installed, because HardScript links with `g++` — if you do not have
one, [`hard doctor`](/docs/tooling/cli) will say so plainly.

## Prerequisites

- A C++23 compiler (`g++` 13 or newer, or `clang++` 17 or newer)
- `git`, if you intend to use the registry
- About two minutes

## Steps

<Steps>
<Step>

### Install the toolchain

```bash
git clone https://github.com/developer-rs5/hardscript-1.git
cd hardscript-1
cargo install --path cli --locked
hard doctor
```

The package is `cli` and the binary it installs is `hard`; `--locked` uses the
committed lockfile. `hard doctor` is the check that matters — it reports g++,
the runtime and the cache, and prints the exact command it looked for when it
cannot find something. If you would rather not build from source, the
[install page](/install) lists every other method and which of them work today.

</Step>
<Step>

### Create a project

```bash
hard new hello
cd hello
```

`hard new` writes `main.hard`, a `hard.toml` manifest, and a `.gitignore`. The
project layout is deliberately flat: one source file, one manifest.

</Step>
<Step>

### Write a route

Replace `main.hard` with this. It is the program on the [introduction](/docs/introduction)
page, with a store added so the data survives a restart:

```hard title=main.hard
bring http

bring json

bring fs

app @8080

model User = users [
    id => Int #id,
    email => Email,
    name => Str,
]

store <- ".hard/users.json"

GET "/users" :: {
    ?(fs.exists(store)) {
        <- json.parse(fs.read(store))
    }
    fs.write(store, "[]")
    <- json.parse(fs.read(store))
}

POST "/users" :: (body = User) {
    ?(!fs.exists(store)) {
        <- { status: 503, error: "store not initialised: call GET /users first" }
    }
    users <- json.parse(fs.read(store))
    created <- { id: body.email, name: body.name }
    fs.write(store, json.stringify(users + [created]))
    <- { status: 201, user: created }
}
```

</Step>
<Step>

### Run it

```bash
hard run
```

The server binds to port 8080. A `hard run` build is a development build: it
compiles with the cache on and without release optimisation. For timings that
mean something, use [`hard bench`](/docs/tooling/cli).

</Step>
<Step>

### Call it

```console
$ curl -s localhost:8080/users
[]
$ curl -s -X POST localhost:8080/users \
    -H 'content-type: application/json' \
    -d '{"email":"ada@example.com","name":"Ada"}'
{"status":201,"user":{"id":"ada@example.com","name":"Ada"}}
$ curl -s -X POST localhost:8080/users \
    -H 'content-type: application/json' \
    -d '{"email":"grace@example.com","name":"Grace"}'
{"status":201,"user":{"id":"grace@example.com","name":"Grace"}}
$ curl -s localhost:8080/users
[{"id":"ada@example.com","name":"Ada"},{"id":"grace@example.com","name":"Grace"}]
```

<Callout kind="warning" title="The GET comes first, and that is not incidental">
The store is a file, and the first `GET` is what creates it. A `POST` before
any `GET` does not create it — it answers the guard above with
`{"status":503,…}`, which is the honest answer for a store that is not there
yet. The order above is the order the program works in, and every line of it was
run before it was written down.
</Callout>

</Step>
</Steps>

## Verify

Add a test to the same file and run it. Tests live next to the code they
describe, and they call routes the way a client would:

```hard title=main.hard
bring http

bring json

bring fs

app @8080

model User = users [
    id => Int #id,
    email => Email,
    name => Str,
]

store <- ".hard/users.json"

POST "/users" :: (body = User) {
    created <- { id: body.email, name: body.name }
    <- { status: 201, user: created }
}

test "a created user comes back" {
    created <- POST "/users" { { email: "grace@example.com", name: "Grace" } }
    expect created.body.status == 201
    expect created.body.user.name == "Grace"
}
```

```console
$ hard test
running .hard/main

HardScript test run
==================
  ok   expect created.body.status == 201
  ok   expect created.body.user.name == "Grace"

==================
2 passed, 0 failed
```

A test that passes means the route built, the body parsed, and the response
shaped as expected — `hard test` compiles before it runs anything.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `g++: command not found` | No C++ compiler on `PATH` | Install one, or run `hard doctor` for the exact command it looked for |
| `error[HS0002]` on a route | The path is unquoted, or the `::` is missing | Routes are `GET "/path" :: { }` |
| Port already in use | Another process holds 8080 | Change `app @8080` and call the new port |
| `main.hard not found` | You are one directory too high | Files default to `main.hard` in the current directory |

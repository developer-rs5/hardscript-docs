A model is a name, a table, and a list of fields. It is a declaration, not a
class: nothing is instantiated, and the fields are the schema the ORM and the
migration tools read.

## Explanation

The parser accepts **two** forms for the same declaration. They are not
interchangeable, and the difference is the sharpest edge in the language.

```text
model User = users [          the bracket form
    id => Int #id,
    email => Email,
]
```

```text
model User {                 the brace form
    id : Int @id,
    email : Email,
}
```

| | Bracket form | Brace form |
| --- | --- | --- |
| Table name | Explicit: `= users` | Defaults to the model name, lowercased |
| Field | `field => Type` | `field : Type` |
| Field separator | Comma | Newline |
| Attribute | `#id`, `#unique` | `@id`, `@unique` |
| Optional marker | Not accepted | `?` |
| Default value | Not accepted | `= value` |

## Syntax

```text
model Name = table_name [
    field => Type #attr,
    other => Type,
]
```

Field types seen in models: `Int`, `Str`, `Float`, `Bool`, `Email`. A field type
is a name, so anything the ORM recognises can appear here.

## Examples

A model with a primary key, a unique constraint, and a timestamp — the bracket
form, which is the one to write:

```hard title=main.hard
bring http

bring json

app @8080

model User = users [
    id => Int #id,
    email => Email #unique,
    name => Str,
    active => Bool,
    score => Float,
    created => Int #created,
]

GET "/users" :: {
    <- []
}
```

## Performance

- A model is a schema, not code. Declaring one costs nothing at runtime, and no
  table is created until a migration runs.
- Field types are checked when the model is used, so a mismatch is a compile
  error rather than a query that returns nothing.
- Index attributes (`#id`, `#unique`, `#created`) describe the table the
  migration will build. They do not slow anything down; leaving them off makes
  every lookup a scan.

## Best practices

- Always give `#id`. It is how a row is addressed, and a model without one cannot
  be the target of a lookup by key.
- Mark anything you will look up by `#unique` if it must not repeat, and
  understand that `#unique` is a constraint and not an index unless the
  migration creates both.
- Name the table in the bracket form, even when it matches the model name. The
  explicit form survives a rename.
- Keep types honest. `created => Int #created` is a Unix timestamp, and
  storing a formatted date in it makes every comparison a string comparison.

## Common mistakes

| Written | Result | Write instead |
| --- | --- | --- |
| `model User = users [ id => Int @id ]` | `@` is not accepted here | `id => Int #id` |
| `model User { id : Int #id }` | `#` is not accepted here | `id : Int @id` |
| `model User = users [ id => Int ]` | No key: nothing can address a row | Add `#id` |
| `model users` | Lowercase, and no table name | `model User = users [ … ]` |
| `model User = users [ id => Int, name => Str name => Str ]` | A missing comma between fields | Fields are comma-separated |
